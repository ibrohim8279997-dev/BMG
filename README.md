# BMG — Build Market Group (MVP)

Строительный маркетплейс Узбекистана с расчётом материалов под объект. Требования: `docs/BMG_architecture_and_functionality.docx`,
задание на MVP: `docs/BMG_Claude_Code_MVP_prompt.docx`.

MVP проверяет три риска: готовы ли продавцы работать через комиссию, достаточно ли точен калькулятор, оставляют ли клиенты предоплату.

## Состав
- `backend/` — Django 5 + DRF. SQLite по умолчанию, PostgreSQL через `DATABASE_URL` (сырого SQL нет).
- `frontend/` — Next.js 15 (серверная отрисовка публичных страниц), 3 языка, 2 темы, адаптивность. Все тексты — `frontend/src/i18n/{uz,ru,en}.json`.
- Браузер ходит на один адрес: Next.js проксирует `/api`, `/admin-api`, `/sitemap.xml`, `/robots.txt` на Django (cookie same-origin, без CORS, сессия в HttpOnly-cookie, CSRF-токен на каждую запись).

## Запуск (разработка)
```bash
cd backend && pip install -r requirements.txt
printf 'DJANGO_DEBUG=1\nDJANGO_SECRET_KEY=dev-only\n' > .env
python manage.py migrate && python manage.py seed_demo      # демо-категории, продавец, ДЕМО-нормы
python manage.py runserver 127.0.0.1:8000
cd ../frontend && npm install && npm run build && npm start   # или npm run dev
```
Без токена бота в DEBUG код входа показывается на экране (`DEV:`). Суперадмин: `python manage.py create_superadmin <login>` (выдаст QR-ссылку для приложения-аутентификатора и 8 резервных кодов); вход на `/ru/admin`.

Telegram: положите `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET` в окружение сервера и выполните `python manage.py set_telegram_webhook https://ваш-домен`. Бот делает только одно: привязывает номер (кнопка «поделиться контактом», чужой контакт отклоняется) и присылает одноразовые коды.

## Что реализовано
Вход через Telegram (код 150 с, лимит попыток, лимиты по номеру и IP, ограничение регистраций с адреса) · роли клиент/продавец + согласия ·
кабинет продавца (импорт Excel с автоподбором и ручной правкой колонок, обязательные остаток и категория, ИИ предлагает категорию, доставка по регионам, документы и фото, аналитика и маржа по желанию, «Спросить у ИИ», запрос выплаты) ·
каталог, заявка на объект, зоны, калькулятор (нормы от ИИ с веб-поиском, цены только из предложений продавцов, предупреждение «ориентировочно» на экране) ·
корзина, баланс, Click на единый счёт, предоплата, возвраты по вине клиента/продавца/BMG ·
суперадминка (роли и права, одобрение продавцов, комиссии по продавцу и уровню, жалобы, журнал аудита, настройки предоплаты и порога, переключатель проверки личности — по умолчанию выключен, 2FA, IP, резервные коды) ·
номера продавцов скрыты, каждое раскрытие в журнале · SSR, hreflang, JSON-LD, sitemap на 3 языках.

## Добавлено по отчёту `docs/BMG_hisobot.pdf` (закрыты пробелы, которые можно закрыть без внешних ключей)
- **Отзывы и рейтинг продавцов**: отзыв только после доставки, один на заказ и продавца, автор не показывается; рейтинг = среднее видимых отзывов; модерация (скрыть) в суперадминке. Значок «Подтверждён BMG» ставится при ручном одобрении продавца.
- **Обход платформы**: суперадминка → «Обход платформы»: клиент открыл номер продавца, а заказ отменён или не закрыт дольше `bypass_check_days` (по умолчанию 3) — BMG связывается с продавцом. Это список для людей, а не автоматическое наказание.
- **Выручка и качество**: MRR (прошлый полный месяц), ARR = MRR × 12, динамика за 12 месяцев, кто сколько платит комиссии; метки продавцов good/bad/neutral по видимым правилам (возвраты по вине продавца, жалобы, доля выполненных).
- **Отчёты CSV** (право `finance`): заказы, операции по балансам, комиссии, возвраты, расчёты с продавцами, балансы клиентов отдельной таблицей. Защита от формул в Excel; каждая выгрузка пишется в журнал.
- **Описания категорий ИИ**: ИИ готовит текст на 3 языках, он скрыт, пока сотрудник не проверит и не утвердит; любая правка снимает утверждение.
- **Контакты BMG для жалоб** (настройки `support_*`): на странице продавца и в подвале. **Cookie-политика** и **оферта продавца** (структура и ЧЕРНОВИК, нужен юрист).
- **SEO-страницы по запросам** «категория + город» (`/ru/prices/cement/Tashkent`): только при наличии живых предложений с доставкой в город; в sitemap на 3 языках.
- **Redis в проде**: `CACHE_BACKEND=django.core.cache.backends.redis.RedisCache` и `CACHE_LOCATION=redis://...` (лимиты запросов и блокировки админки живут в кеше; без Redis они локальны для процесса).

## Пункты «после MVP» (раздел 6 отчёта)
- **3D-дом (Three.js)** на главной и в калькуляторе: выбранные зоны подсвечиваются, камера плавно приближается к ним, дом можно повернуть мышью/пальцем. Реальные клики по частям дома выбирают зоны. Three.js грузится отдельным куском только там, где дом показывается.
- **Две версии сайта**: полная и лёгкая. Авто-определение до первой отрисовки (экономия трафика, 2G/3G, ≤2 ГБ памяти или ≤2 ядра, «уменьшить анимацию»), кнопка в шапке: авто → полная → лёгкая. Лёгкая: плоский SVG-дом вместо 3D, без анимаций, размытия и теней; структура и функции те же.
- **Описание проекта голосом или текстом**: микрофон (распознавание речи делает сам браузер) → ИИ заполняет форму объекта и выбирает категории; цены показываются только из предложений продавцов, значения вне допустимых отбрасываются, форма заполняется только после нажатия клиентом.
- **Налоговая бухгалтерия** (переключатель `tax_accounting_enabled`, по умолчанию выключена): счета за комиссию по закрытым месяцам, нумерация, статусы черновик → выставлен → отправлен (номер вносит сотрудник), отчёт по НДС 12%, CSV. **BMG ничего не отправляет в налоговую сам**; ЭЦП/SoliqOnline/Didox/Faktura.uz не подключены. НДС считается включённым в комиссию: это допущение, которое должен подтвердить бухгалтер вместе с правилами для налоговых агентов с 12.12.2026.
- **Финансовая модель** (суперадминка → «Финансовая модель»): 12-36 месяцев, поля заполняются по реальным заказам, расходы задаёт владелец; выручка = комиссия онлайн + предоплата при наличных, минус НДС и возвраты; месяц выхода в плюс и потребность в деньгах.
- **Вход через Google**: включается переменной `GOOGLE_CLIENT_ID` (и для Django, и для Next.js: CSP открывает `accounts.google.com` только при ней). Токен проверяется у Google, аккаунты связываются только по Google-id, никогда по e-mail; сотрудники входят только через `/admin`. Реально с Google не проверялось (в тестах проверка подменена).
- **Приложение для телефона — PWA**: манифест, иконки, service worker и офлайн-страница; ставится на главный экран Android и iOS и использует тот же сервер. Service worker не трогает `/api` и `/admin-api`.

**Осознанно не сделано** (нужны внешние ключи, юрист, решение владельца или инструменты, которых здесь нет): нативное Android-приложение на Kotlin (в среде нет Android SDK, непроверяемый код я не добавлял; PWA закрывает установку на телефон, а нативное приложение стоит делать на тот же API); реальные платежи Click/Payme/карты и выплаты через банк; каптча; CSP без `unsafe-inline` (нужен nonce в Next); проверка на реальных устройствах; возвраты по вине BMG зачисляются на баланс сразу, срок 3+1 день остаётся записью; многопровайдерный ИИ уже есть в коде, но вживую не вызывался (нужны ключи).

## Принятые допущения (проверьте — это решения, которых в документах нет)
1. **Деньги.** Клиент платит `T` = товары + доставка. Предоплата 5% (`T`) — часть этой суммы. Продавец получает `T − комиссия` после доставки; комиссия считается только с товаров. При оплате «предоплата + наличные» BMG получает только предоплату; комиссия с наличной части **не взимается** (открытый вопрос из документа).
2. **Возвраты** зачисляются на баланс клиента (не на карту). Для вины BMG срок 3 рабочих дня + 1 запасной записывается в возврат, но зачисление на баланс мгновенное.
3. **Нормы расхода** создаёт ИИ с веб-поиском, кешируются, помечаются «не проверено» до проверки сотрудником. `seed_demo` кладёт ДЕМО-нормы только для разработки. Если ИИ недоступен — ошибка, а не выдуманные цифры.
4. **ИИ-провайдеры:** `claude`, `openai` («Codex»; модель по умолчанию `gpt-4.1`, поменяйте переменной), `gemini`, `grok`, `groq` («GrokQ» понят как Groq). Перебираются по порядку `AI_PROVIDERS`. Имена моделей и API проверьте при подключении ключей — вживую они не вызывались.
5. **Excel:** принимается только `.xlsx` (старый `.xls` — тот же запрет, что и на `.doc`).
6. **Геометрия калькулятора** (площадь стен, крыши) — грубые формулы в `apps/calculator/service.py`; доставка по заказу считается один раз на продавца.
7. Тексты юридических документов — заглушки `DRAFT`; их нужно заменить после консультации с юристом.

## Что осталось / риски
- Click не проверялся на реальных ключах: логика покрыта тестами по спецификации Shop API; нужны `CLICK_*`, список IP Click и тестовый платёж.
- Нужен Redis для лимитов запросов в проде (локальный кеш не общий между процессами).
- CSP фронтенда допускает `unsafe-inline` для скриптов (требование Next.js без nonce); следующий шаг — nonce.
- Не сделано по документу (вне MVP): 3D-дом, облегчённая версия, голос, налоговая бухгалтерия, Android, финмодель.
- Открытые вопросы: юрист (хранение денег клиентов, невозвратная предоплата, оферта), резервные копии на сервере (где, как часто, проверено ли восстановление), нормы расхода — кто проверяет.
