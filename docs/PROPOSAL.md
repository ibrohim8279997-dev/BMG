## 1. Структура проекта

```
BMG/
├── backend/                  Django + DRF
│   ├── config/               settings (base/dev/prod), urls, wsgi; всё через env
│   └── apps/
│       ├── accounts/         пользователи, роли, вход через Telegram, согласия
│       ├── sellers/          профиль продавца, одобрение, документы, регионы доставки
│       ├── catalog/          категории, товары, предложения (цена+остаток), импорт Excel
│       ├── calculator/       объект (заявка), зоны, нормы расхода, расчёт
│       ├── orders/           корзина, заказы, позиции по продавцам
│       ├── payments/         баланс, транзакции, Click, возвраты (отдельный журнал)
│       ├── commissions/      ставки по продавцу и уровню
│       ├── support/          жалобы
│       ├── audit/            журнал аудита (раскрытие номеров, действия сотрудников)
│       ├── ai/               «Спросить у ИИ», подбор категории, учёт запросов
│       ├── adminpanel/       суперадминка: 2FA (TOTP), IP-лимит, резервные коды
│       └── uploads/          проверка файлов по содержимому, хранение вне web-root
├── frontend/                 React + Node (см. вопрос 1)
│   └── src/{pages,components,i18n/{uz,ru,en}.json,theme,api}
├── docs/
└── docker-compose.yml        Django + PostgreSQL (SQLite по умолчанию в dev)
```

## 2. Модели данных (основное)

- **User**: telegram_id, телефон, роль (client/seller/staff), язык, дата согласий с версиями документов.
- **StaffRole / Permission**: роли и права выдаёт суперадмин. Предустановлены: суперадмин, колл-центр, поддержка, менеджер по продавцам, бухгалтер.
- **TelegramLoginCode**: хеш кода, срок 2–3 мин, число попыток, IP, телефон. Лимиты по номеру и IP.
- **Seller**: статус (pending/approved/blocked), регионы, контакты, `phone_hidden`, флаг проверки личности (глобальный переключатель по умолчанию выкл).
- **SellerDocument / SellerPhoto**: файл (вне web-root), тип, размер, публичность.
- **DeliveryRule**: seller, регион, ограничения, стоимость.
- **Category** (дерево, переводы uz/ru/en) и **Product** (название, категория обязательна, описание на 3 языках).
- **Offer**: product, seller, цена, остаток (обязателен), себестоимость (необязательна). Цены только отсюда.
- **PriceImport**: файл, предложенное соответствие колонок, правки продавца, статус (draft/confirmed).
- **ObjectRequest**: тип (квартира/дом/ЖК), площадь, этажность, комнаты, город. **Zone**: стены, пол, потолок, крыша. **ConsumptionNorm**: категория × тип объекта × зона → норма; источник и проверяющий обязательны.
- **Cart / Order / OrderItem**: сумма считается на сервере из Offer. Статусы заказа, продавец видит только свои позиции.
- **Wallet / LedgerEntry**: виртуальный баланс в сумах, только добавление записей. **Prepayment**: 5% от заказа (порог для мелких заказов задаётся настройкой).
- **ClickTransaction**: click_trans_id (уникален), сумма, подпись, сырой payload, статус. Отдельный журнал.
- **Refund**: причина (client/seller/bmg), удержание у продавца (**SellerHold**), срок BMG: 3 рабочих дня + 1.
- **CommissionRate**: по продавцу или уровню; считается только со стоимости товара, без доставки.
- **Complaint**, **AuditLog** (актор, действие, объект, IP, время; раскрытие номера = запись), **AIUsage** (запросы, токены, стоимость), **LegalDocument** (3 языка, версия, дата вступления), **Setting** (переключатели).

## 3. API (REST, `/api/v1/`)

| Область | Эндпоинты |
|---|---|
| Auth | `POST auth/telegram/request-code`, `auth/telegram/verify`, `auth/register` (роль + согласия), `auth/logout` |
| Продавец | `sellers/me`, `sellers/me/documents`, `sellers/me/delivery-rules`, `sellers/me/imports` (upload → mapping → confirm), `sellers/me/offers`, `sellers/me/analytics`, `sellers/me/orders` |
| Каталог | `categories`, `products`, `products/{id}/offers`, `sellers/{id}` (публичный, без номера), `sellers/{id}/phone` (раскрытие, пишет аудит) |
| Клиент | `objects` (заявка), `objects/{id}/zones`, `objects/{id}/calculate`, `objects/{id}/suggest` (подбор по ценам) |
| Заказы | `cart`, `orders`, `orders/{id}` |
| Платежи | `wallet`, `wallet/topup` (создаёт счёт Click), `payments/click/prepare`, `payments/click/complete` (только с разрешённых IP, подпись, сумма из БД, идемпотентность) |
| Возвраты | `orders/{id}/refund` (инициирует поддержка) |
| ИИ | `ai/ask`, `ai/suggest-category` |
| Админка | отдельный префикс и вход: `admin-api/` (продавцы, комиссии, роли, жалобы, аудит, переключатели) |
| SEO | `sitemap.xml`, `robots.txt` |

## 4. Безопасность: как закладываем

Только ORM. Файлы: проверка по содержимому (magic bytes, структура docx/xlsx), лимиты 5/10/20 МБ, PDF до 2 страниц, `.doc` отклоняется, хранение вне web-root, раздача через контролируемый эндпоинт. Админка: TOTP + резервные коды, IP allowlist, отдельный вход. Лимиты запросов, CSRF, security headers, капча на регистрации. Тесты: SQL-инъекции, подмена суммы, повтор Click-уведомления, доступ продавца к чужим заказам, раскрытие номера без аудита.

1. Каркас Django, настройки из env, i18n-основа, базовые модели `accounts`.
2. Вход через Telegram-бот, роли, согласия, лимиты.
3. Продавец: профиль, одобрение, документы/фото, загрузка файлов.
4. Каталог, импорт Excel с подбором колонок, остатки, категории (+ИИ).
5. Заявка на объект, зоны, калькулятор.
6. Корзина, заказы, баланс, Click, предоплата 5%, возвраты.
7. Суперадминка (2FA, роли, комиссии, жалобы, аудит).
8. Фронтенд: три языка, две темы, адаптивность.
9. SEO (SSR, sitemap), тесты безопасности, ревизия.
